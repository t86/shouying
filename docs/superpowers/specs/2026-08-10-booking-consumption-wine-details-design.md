# 预订系统查看消费与存取酒明细设计

## 目标

在“业务配置 / 规则配置”中，为“限制预订系统显示金额”增加两个受控子开关，并在咨客预订系统的卡台菜单中按配置显示“查看消费明细”和“查看存取酒明细”入口。两个入口均为只读展示，复用点单系统“我的点单”已有的数据源和数据转换规则。

## 范围

本次变更包括：

- 后台规则页读取、编辑和保存两个新开关。
- 预订卡台页读取门店业务配置并据此控制两个菜单入口。
- 按卡台和翻台流水查看消费明细。
- 按卡台和翻台流水查看存取酒明细。
- 抽取可复用的只读数据转换逻辑和自动化测试。

本次不包括：

- 在咨客系统中退单、优惠、更换套餐、打印或执行存取酒操作。
- 修改 `wo/list` 或门店业务配置接口。
- 修改点单系统现有权限模型。
- 引入新的全局状态或改变点单系统当前卡台。

## 已有实现

- 规则配置页面位于 `src/views/ManagementSystem/BMS/terminalRules/terminalRules.vue`。
- 门店业务配置接口已经封装为 `this.$api.BMS.terminalRules.reqGetTime` 和 `reqSubmitTime`。
- 预订卡台菜单由 `src/views/Book/cardMachine.vue` 的 `getCardOptions` 生成，菜单定义来自 `src/utils/config/card.js`。
- 点单系统“我的点单”页面通过 `wo/list` 读取当前卡台和翻台流水；响应中的 `records` 是消费明细，`wine_ops` 是存取酒明细。

## 接口契约

### 读取配置

`POST org/get_org_biz_cfg`

本功能使用以下字段：

- `limit_book_csm_amt`: `1` 限制显示金额，`2` 不限制。
- `enable_book_csm_dtl`: `1` 开启咨客查看消费明细，`2` 关闭。
- `enable_book_wine_dtl`: `1` 开启咨客查看存取酒明细，`2` 关闭。

字段缺失、接口失败或返回值非法时，两个明细权限均按关闭处理。

### 保存配置

`POST org/save_org_biz_cfg`

页面保留原有请求字段，并增加：

- `enable_book_csm_dtl`
- `enable_book_wine_dtl`

当 `limit_book_csm_amt === 1` 时，无论页面之前保存过什么值，两个子开关均提交为 `2`。

### 读取明细

`POST wo/list`

请求参数：

- `seat_id`: 当前卡台 ID。
- `turnover_cnt`: 当前选择的翻台流水序号。

响应数据：

- `records`: 消费明细列表。
- `wine_ops`: 存取酒明细列表。
- `pay_info`: 消费金额汇总；只读组件可以使用，但不提供结算操作。

`records`、`wine_ops` 或 `pay_info` 缺失时使用安全默认值。

## 配置页面行为

“限制预订系统显示金额”区域增加两个子开关：

- 预订系统查看消费明细
- 预订系统查看存取酒明细

两个子开关仅在“限制预订系统显示金额”关闭时显示并允许编辑。开启金额限制时：

1. 立即把两个前端布尔值重置为 `false`。
2. 隐藏两个子开关。
3. 保存时把两个接口字段提交为 `2`。

从接口读取配置时，如果金额限制已开启，即使服务端错误地返回子开关为 `1`，页面仍把两个子开关归一化为关闭。

## 预订卡台入口规则

预订卡台页面挂载时读取一次 `org/get_org_biz_cfg`。入口最终可见需要同时满足：

1. `limit_book_csm_amt === 2`。
2. 对应的子开关字段为 `1`。
3. 卡台状态允许查看历史或当前流水。

状态矩阵如下：

| 卡台状态 | 条件 | 是否显示已开启的明细入口 |
| --- | --- | --- |
| 空台 | `turnoverCnt === 0` | 否 |
| 空台 | `turnoverCnt > 0` | 是 |
| 锁定 | 任意 | 否 |
| 预订/预留 | 任意 | 否 |
| 开台 | 任意 | 是 |
| 点单未结账 | 任意 | 是 |
| 部分结账 | 任意 | 是 |
| 已结账 | 任意 | 是 |

“查看消费明细”和“查看存取酒明细”相互独立：只为开启的权限生成对应菜单项。配置尚未加载或读取失败时不生成入口，避免在权限状态未知时暴露数据。

## 明细弹窗

两个入口分别打开独立标题的只读弹窗：

- 查看消费明细
- 查看存取酒明细

弹窗不跳转路由，不写入 `orderInfo.currentCardInfo`，也不注册点单系统快捷键。

### 翻台选择

弹窗顶部以“卡台名称-三位流水号”显示翻台标签，例如 `A01-003`。标签按流水号从大到小排列，默认选中最新流水。

空台但有翻台时，最新标签对应最近一次已结束流水。正在营业的卡台，最新标签对应当前流水。

切换标签时按需调用 `wo/list`。同一次弹窗会话内，以 `seat_id + turnover_cnt` 为键缓存成功响应；切换回已读取流水不重复请求。关闭弹窗后清空缓存，重新打开时读取最新数据。

### 消费明细

消费明细复用点单系统“我的点单”的数据转换规则，包括：

- 商品与套餐名称映射。
- 套餐子项展示。
- 正常、结账、退单、优惠和优惠 2 状态。
- 数量、成交单价、小计、服务员和点单时间。
- 金额汇总的单位转换。

咨客弹窗只展示数据，不显示退单、优惠、更换套餐、修改服务员或打印入口。

### 存取酒明细

存取酒明细直接使用 `wine_ops`，展示：

- 存酒或取酒状态。
- 商品名称。
- 规格。
- 数量。
- 存/取酒操作人。
- 存/取酒操作时间。

## 模块边界

为避免把整个“我的点单”页面嵌入咨客系统，本次采用以下边界：

- 纯函数负责配置值归一化、入口可见性判断、翻台标签生成和接口响应默认值处理。
- 可复用的只读表格组件只接收已经转换好的数据，不读取路由或修改 Vuex。
- 点单页面保留原有操作型界面；咨客弹窗组合只读组件。
- `cardMachine.vue` 只负责加载配置、生成入口以及打开对应弹窗。

这样可以共享业务含义和数据显示规则，同时隔离点单操作权限、快捷键和全局当前卡台状态。

## 错误处理

- 配置读取失败：两个入口均隐藏，不阻断卡台页面其他功能。
- 明细读取返回普通失败：保留弹窗，显示服务端错误信息，当前流水展示为空。
- 明细读取抛出异常：保留弹窗，提示“明细获取失败”，当前流水展示为空。
- 数据字段缺失：按空数组或零金额处理，组件不抛异常。
- 快速切换翻台标签：只接受与当前选中流水匹配的响应，避免较慢请求覆盖新选择。

## 测试策略

使用仓库已有的 Node `node:test` 风格测试纯函数和关键源码行为，遵循先失败、后实现的顺序。

自动化测试覆盖：

- 配置字段 `1/2` 与布尔值互转。
- 金额限制开启时两个子权限强制关闭。
- 两个入口按各自开关独立显示。
- 状态矩阵中的普通空台、带翻台空台、预订/预留和营业中状态。
- 翻台标签倒序及默认最新流水。
- `records`、`wine_ops` 和 `pay_info` 缺失时的安全默认值。
- 同一流水的响应缓存和关闭弹窗后的缓存清理。
- 过期异步响应不会覆盖当前选中流水。

完成后执行相关单测、全部 Node 测试以及生产构建。人工验收至少覆盖：

1. 父开关开启时子开关被关闭且隐藏。
2. 两个子开关可分别控制两个入口。
3. 普通空台和预订/预留卡台无入口。
4. 带翻台空台和营业中卡台有对应入口。
5. 多次翻台时可切换流水，并分别显示消费与存取酒数据。
