# 存取酒通知打印机设计

## 目标

为“存酒仓库”终端新增一台可选的“存取酒通知小票打印机”。配置后，每次存酒或取酒会在原有小票打印流程中额外向这台打印机发送一张给仓库人员的通知小票。

## 范围

- 终端列表使用 `lic/list` 返回的 `npi`（通知打印机 Id）及 `npn`（通知打印机名称）；列表中的打印机名称区域同时展示该名称。
- “配置存酒仓库打印机”弹窗在“取酒小票打印机”下方增加“存取酒通知小票打印机”下拉框。
- 通知打印机下拉框复用取酒小票打印机的普通打印机选项（`lic/get_prts`）。
- `lic/save_prt` 的保存请求增加 `wine_notify_prt_id`；未配置时传 `0`。
- 追踪既有存酒、取酒小票的生成和发送逻辑。每次原小票任务构建完成后，若当前终端配置了通知打印机，复制同一份内容、将目标打印机替换为通知打印机，并将标题改为：
  - 存酒：`{场所名称}存酒通知`
  - 取酒：`{场所名称}取酒通知`
- 除标题和目标打印机外，通知单完整复用既有存酒/取酒小票的字段、明细表格、总计（适用时）、时间与样式；不新增字段，不修改现有原始小票的打印行为。

## 不在范围内

- 不改变非“存酒仓库”终端的配置界面或请求语义。
- 不改变补打存取酒小票的业务规则，除非它复用同一实时打印任务而天然获得通知单。
- 不修改后端接口契约以外的服务端业务实现。

## 数据流与容错

1. 打开存酒仓库终端配置时，用 `npi` 回填通知打印机选项；列表用 `npn` 显示其名称。
2. 保存时同时提交原有 `prt_id`、两种存酒打印机 Id 与 `wine_notify_prt_id`。
3. 存/取酒完成后，原有小票照常生成；若通知打印机 Id 为正数，再生成一张仅标题和目标打印机不同的通知小票。
4. 未配置通知打印机时不额外创建打印任务；通知打印失败沿用当前打印任务的错误处理方式，不影响已存在的小票打印结果或存取酒业务结果。

## 验收

1. 存酒仓库终端可选择、回显、清除通知打印机；保存请求正确传递 `wine_notify_prt_id`。
2. 列表可显示后端返回的通知打印机名称。
3. 配置通知打印机后，存酒产生一张标题为“xxx场所存酒通知”的小票，字段及样式与存酒小票一致。
4. 配置通知打印机后，取酒产生一张标题为“xxx场所取酒通知”的小票，字段及样式与取酒小票一致。
5. 未配置通知打印机时，不新增通知打印任务，既有存取酒小票保持不变。
