# 商户号管理线上收款开关设计

## 背景

收银系统 `更多功能 -> 商户号管理` 需要增加“启停商户号线上收款功能”。

需求约束：

- 关闭开关后，该商户号不能用于线上收款。
- 主页面现有配置项不需要联动置灰、禁用或阻止保存。
- 需要兼容多主体场景。
- 提示文案只作为需求说明，不额外渲染黄色提示框。

## 目标

- 在商户号管理页面内提供独立的线上收款开关配置区。
- 用户可以查看门店全部商户号的线上收款启停状态。
- 用户切换任一商户号开关后，立即调用后端接口保存状态。
- 多主体场景下，开关按“商户号”维度统一展示，不按主体拆分。

## 接口设计

### 读取

继续使用：

- `org/get_cnl_cfg_grp`

新增返回：

- 关闭的渠道 id 列表

前端用途：

- 读取商户号列表基础信息
- 读取当前哪些商户号处于关闭状态

### 保存

新增接口：

- `org/save_cnl_cfg_openclose`

前端用途：

- 切换某个商户号开关时保存当前状态

## 交互设计

### 展示位置

在 [drawerMerchant.vue](/Volumes/WORK/xuzheng/shouyin/src/components/money/drawerMerchant.vue) 中增加独立的“线上收款功能”配置区块。

该区块与现有：

- 自动切换商户号
- 默认商户号
- 时段额度控制
- 卡台绑定商户号

并列存在，不互相联动。

### 列表内容

每条商户号展示一行，内容为：

- 商户号
- 持卡人姓名
- 银行卡号
- 开关状态

展示格式：

- `商户号 -- 持卡人姓名 -- 银行卡号`

银行卡号允许做脱敏展示，保持与页面现有展示方式一致；若现有商户号管理页已有原始字段和展示习惯，则优先复用现有风格。

### 开关规则

- 默认状态为开启
- 若商户号 id 在“关闭渠道 id 列表”中，则显示关闭
- 用户点击开关后立即请求保存
- 保存成功后更新本地状态
- 保存失败后回滚开关并提示错误

## 多主体处理

多主体场景下，开关展示规则如下：

- 仍展示门店全部商户号
- 不按主体分页或拆分
- 不复制到 `全局配置 / 主体A / 主体B` 各自独立维护

原因：

- 该能力控制的是“商户号是否可线上收款”
- 不是主体归属或主体配置
- 同一商户号在不同主体页签出现不同状态会造成歧义

## 数据结构建议

前端为每个商户号补充一个本地字段，例如：

- `onlineCollectEnabled: boolean`
- `savingOpenClose: boolean`

用途：

- `onlineCollectEnabled` 控制当前开关展示
- `savingOpenClose` 控制单行保存中状态，避免重复点击

## 错误处理

- `get_cnl_cfg_grp` 未返回关闭列表时，前端按全部开启处理
- 若保存接口失败，恢复用户切换前的状态，并提示后端错误
- 若商户号列表为空，则该区块不展示列表，仅保留空状态

## 验证

至少验证以下场景：

- 单主体下列表正确展示全部商户号
- 多主体下仍只展示一份全量商户号开关列表
- 已关闭商户号能正确回显为关闭
- 开关切换后请求成功，状态保持
- 开关切换后请求失败，状态回滚
- 原有默认商户号、时段额度控制、卡台绑定保存逻辑不受影响
