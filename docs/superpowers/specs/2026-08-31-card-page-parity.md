# 三系统卡台页面对照修复

用户要求：Flutter 按原项目实际路由页面尽量一比一还原，不能把共享数据组件当作共享业务页面。此轮先修复安卓版点单页，并纠正共享页面对预定/收银的错用配置；不改后端、不新增离线业务。

## 页面真值

| 页面 | 原路由组件 | 日期栏 | 默认选择 | 搜索 | 更多菜单 |
| --- | --- | --- | --- | --- | --- |
| 预定 | Book/cardMachine.vue | canDoList 原标签 | 全部 | 卡台/客人/手机/订位人 | 独立7项 |
| 点单 | Order/newOrderCard.vue | 无 | 我的卡台 | 无 | 低消进度统计表、鸡尾酒明细表；module5显示估清商品 |
| 收银 | Money/moneyCard.vue | 无 | 全部 | 卡台/客人/手机尾四位 | 独立37项 |

点单主题使用实际导入的 `style/order/newOrderCard.less`，浅色底、蓝色选中区域，不采用旧版 orderCard 或预定的深色样式。

点单会员充值入口需要模块91/92/93任一；存酒模式入口需要模块1。安全模式隐藏点单/收银更多入口，但不能擅自用它隐藏点单充值和存酒入口。预定更多不受安全模式隐藏。

账户菜单另列：预定是修改密码/退出登录；点单和收银还含授权密码。切换系统保留为用户此前明确要求的额外账户动作，开发设备诊断单独标明，不能混进原业务更多菜单。

## 数据与交互

- 当前岗位角色/模块来自13/41，安全模式来自54，必须支持完整、增量和晚订阅回放。缺失/损坏时不默认放行模块入口。
- 我的卡台是14[14]订位人或14[20]历史服务员分号集合精确匹配登录员工；先使用现有授权可见基集再缩小，不新增下属/营销可见范围。
- 个人开台/抵达取39的30/31按卡台累计，不用全场数据冒充个人数，也不直接数状态4。
- 正常点单模式点击卡台不弹存取酒菜单；空台/锁台/预定提示不能点单；存酒模式才展示原有存/取/充公入口。
- 营业日关闭不阻止看卡台。预定保留开启动作；点单/收银提示联系咨客，不出现开启按钮。
- 未实现报表、充值、开单等子业务仍须明确标注待接入；恢复入口不等于完成子业务。原有业务操作任务继续待开发。

## 本轮边界

补齐菜单、账户/底部入口、点单默认选择与只读模式切换、日期/搜索分系统配置、主题以及页面权限元数据。营销全场范围（get_sales_seats/赠送卡台等）、完整顾客字段与搜索、全部业务弹窗和写操作仍由原任务单独验收；不得凭本轮 UI 测试宣布全量等价。

## 验证

先复现 `order more menu never reuses booking system entries`：原实现找不到低消进度统计表。加入三个系统菜单列表、状态和角色/模块/安全模式矩阵测试，点单布局/默认个人过滤/个人统计/模式切换测试，元数据增量撤权/失败关闭/晚订阅测试。执行工作区回归、静态分析、Android构建安装及实际页面截图。看板 LOCAL-001 记录这次还原，TABLE-008 保留业务入口尚未闭环的状态。

### 本轮验证结果

- Flutter 工作区：348/348 测试通过，静态分析无问题。
- Node 与边界回归：183通过、4个 Windows/PowerShell 环境相关跳过，0失败；边界违规0。
- 独立源码复核发现的翻台空台菜单遗漏、未知/损坏权限经重放或后续增量扩大范围问题，均先补红测再修复；card_table 包45个测试独立复跑通过。
- Android arm64 release 编译成功，覆盖安装保留数据。启动可进入系统选择；重启后的真实账号登录和业务页面视觉验收仍需用户完成，未自动猜测或读取密码。
- 仅用户范围内完整已知角色数据可展示卡台范围；缺失/损坏后直到13和41均完整有效的快照前保持关闭，包括未来卡台、统计、心跳、后续合法增量和晚订阅。无岗位的内部feed只保留原始数据，不授予页面权限。
- Windows 未作实机验证。此轮不声称完整业务功能或每个像素与旧版等价；缺少的具体业务操作继续保留在迁移任务中。
