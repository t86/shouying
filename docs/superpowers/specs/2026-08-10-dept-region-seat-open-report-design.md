# 部门实时订台 / 区域开台报表设计

## 背景与目标

在咨客系统“更多功能”中新增“部门实时订台/区域开台”报表，用于同时查看：

1. 各订台部门当前仍有效的实时订台数量。
2. 各区域当前营业日累计开台消费数量。

报表复用现有“入客数据实时汇总表”的抽屉交互、视觉风格和 Excel 导出流程，不在前端重复推导业务统计规则，数量以报表接口返回值为准。

## 入口与交互

- 在 `src/views/Book/cardMachine.vue` 的“更多功能”菜单中，紧邻“入客数据实时汇总”增加“部门实时订台/区域开台”入口。
- 点击入口打开独立的右侧抽屉，标题为“部门实时订台/区域开台表”，宽度与现有实时汇总表一致。
- 每次打开抽屉都重新请求数据，保证展示当前统计结果。
- 抽屉顶部展示“最后刷新时间：{now_time}”和“导出Excel”按钮。
- 底部保留统一的“关闭”按钮。

## 数据接口

### 查询

- 方法：`POST`
- 地址：`/sel/rpt/get_dept_region_seat_open_list`
- 请求体：空对象 `{}`
- 成功条件：`code === 1`
- 数据字段：
  - `now_time`：当前查询时间。
  - `dept_list`：部门实时订台列表。
  - `region_list`：区域累计开台列表。

接口方法放在 `src/api/Book/index.js`，沿用该模块现有的普通 POST 封装。

### 导出

- 方法：`POST`
- 地址：`/sel/rpt/exp_dept_region_seat_open_list`
- 请求体：空对象 `{}`
- 响应：Excel 二进制文件。

接口方法放在 `src/api/Book/index.js`，沿用现有 `binaryFilePost`、文件名响应头和浏览器下载流程。

## 展示结构

抽屉内容分为上下两部分。

### 部门实时订台表

列为：

- 订台部门
- 实时订台数量

接口字段映射：`n` 为部门名称，`c` 为数量。部门名称前导空格不直接渲染为文本，而是转换为左侧缩进，以保留部门层级并避免 HTML 合并空白。后端返回数量为 0 的部门仍正常展示。

表格底部增加“合计”行，合计值为 `dept_list` 中所有 `c` 的数值之和。

### 区域开台总数表

列为：

- 区域
- 开台总数

接口字段映射：`n` 为区域名称，`c` 为数量。后端返回数量为 0 的区域仍正常展示。

表格底部增加“合计”行，合计值为 `region_list` 中所有 `c` 的数值之和。

## 组件边界

新增独立报表抽屉组件，负责：

- 控制自身展示状态。
- 在打开时读取报表。
- 格式化部门层级、计算两部分合计。
- 触发 Excel 导出。
- 展示接口失败提示并向父组件发出关闭事件。

`cardMachine.vue` 只负责菜单入口、抽屉显隐状态和挂载组件。API 模块只负责请求封装。可独立测试的格式化及合计逻辑放入小型工具模块，避免依赖 Vue 运行环境。

## 异常与空数据处理

- 查询返回 `code !== 1` 时，使用接口 `msg` 提示用户；列表保持为空。
- 查询发生网络异常时，不展示错误数据，并记录便于排查的错误信息。
- `dept_list` 或 `region_list` 缺失、不是数组时按空数组处理。
- 空列表显示“暂无数据”，合计显示 0。
- 数量字段缺失或不能转换为有限数值时按 0 处理，防止合计出现 `NaN`。
- 导出响应包含业务错误信息时使用其 `msg` 提示；网络失败时记录“导出excel失败”。

## 测试与验收

使用项目现有 Node 测试方式先覆盖纯逻辑，再实现生产代码：

- 部门前导空格可转换为稳定的层级和干净名称。
- 正常数量、字符串数量、空列表和无效数量均能得到正确合计。
- 接口模块包含正确的查询、导出路径及请求方式。
- 页面包含新菜单入口、独立显隐状态和报表组件挂载。
- 组件能展示刷新时间、两张表、0 值行及合计，并能触发导出。
- 定向测试通过后运行现有完整 Node 测试与生产构建，确认无语法、编译或回归问题。

## 非目标

- 前端不自行判断预订、开台、撤台、清台等业务状态；统计口径由后端接口实现。
- 不修改现有“入客数据实时汇总表”的接口或字段。
- 不增加筛选、自动轮询、打印或自定义导出文件名功能。
- 不重构与本功能无关的咨客页面代码。
