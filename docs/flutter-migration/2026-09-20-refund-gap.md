## S2.P4.T02 我的点单未结退单

源：主仓src/components/order/myOrder/drawerMyOrder.vue，orderBack约749–810行、数量约583–623/1561–1578行。

初次复核时Flutter OrderMealScreen._refund只选择理由，固定整行数量、空金额、本人授权。初始差异清单如下；实施进展见后文，不能把旧状态当作当前实现：

- 普通点单身份默认数量1，可选择1至pc的整数；线上订单只能整笔，小费类型4数量固定1。
- 商品类型3/5/8：点单身份数量锁定全退、back_amt使用原订单pa；收银身份允许选择数量/输入金额，部分数量须重新输入金额，不得超过原pa。其他商品back_amt始终空字符串。
- authStatus==4指操作者身份，不是订单at；pp==0也不能替代商品类型判断。商品已不在当前区域目录时，不能猜成普通商品。
- code==2才升级到授权页：他人账号+MD5大写密码，或刷卡pass_type=2；当前API/loader固定空授权字段、pass_type=1。
- 请求前复核当前会话、卡台与订单；普通/线上分别使用/wo/back与/wo/ol_unpay_back。金额单位为元。

最小实施顺序：补可靠商品类型/操作者上下文 → 退单数量和金额草稿 → API授权字段与code=2识别 → 授权交互 → 数量/金额/线上/身份边界回归。

引用的2026-08-13-order-refund-quantity-keyboard-design.md仅规定Android数量键盘体验，不可当通用金额协议。取消、成功、进入授权时应移除焦点，不改全局键盘。
